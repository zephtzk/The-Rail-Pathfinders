# Commute Copilot: clearer public-transport journeys

[Open the prototype](https://commute-copilot-nebula.simhongmen.chatgpt.site) · [View the source code](https://github.com/zephtzk/The-Rail-Pathfinders)

Commute Copilot is a phone-friendly Singapore public-transport web application developed for NEBULA X PS2. It helps commuters compare journeys, follow one accepted trip, and find practical assistance when travel becomes confusing. Its focus is clear next actions, accessible presentation, and control over changes to the journey.

Users can plan between supported stations and bus stops, compare estimated arrival times, walking and transfers, and start their chosen route. Current trip presents the current and next instruction, manual progress confirmation, and direct End, Pause/Resume and Cancel controls. Simple guidance and an 80–200% text-size setting support different reading preferences. Show to staff presents an assistance message, including an optional custom message that is displayed as literal text and is not retained after a reload.

Services brings together service information, nearby listed lifts and toilets, and clearly labelled demonstration incidents. Demonstration controls let users save simulated incidents and replay travel disruptions against the selected journey and packaged data. Alternative-route proposals remain subject to the traveller's acceptance; a new search does not silently replace an accepted trip. These demonstrations show how disruption response works without presenting fictional incidents as live operator reports.

Caregiver sharing provides a read-only link to a planned journey. The recipient can view and refresh that trip, but cannot edit it, control the provider's journey, or obtain geographic location through this link. The provider can refresh the shared plan or cancel sharing. Sharing uses persistent server storage. Journey notifications are disabled in the current build. Saved places, personal journey history and spending records remain in the user's browser. Spending supports estimated fares, user-confirmed charges, adjustments and budgets; it is not connected to a payment account.

The core demonstration uses packaged transport data and does not require the judges to supply an API key. Rail data covers 18 September–31 December 2026, subject to service calendars; the reviewed bus-data window is 18 September–2 October 2026. Bus travel and waiting times are estimates. Optional address routing and live information depend on server configuration and provider availability. Prepared guidance can be used offline after the app confirms readiness; live information, new address requests and street-map tiles are not promised offline.

The prototype does not establish a complete verified step-free indoor corridor, exact facility entrances, or current lift/toilet availability. Facility pins and route geometry may be approximate. Device coordinates cannot confirm an indoor floor, boarding or arrival. These limits are shown alongside the relevant guidance rather than converted into unsupported accessibility assurances.

The source repository includes the application, routing and sharing services, pinned data, build scripts, automated tests and setup instructions. Recorded validation covers routing, simulated incidents, sharing permissions, journey controls and enlarged-text layouts. Browser automation is evidence of software behavior, not physical-phone, indoor-navigation or real-station validation. The README provides the current demonstration steps and release details; older phase reports are retained as historical evidence.
