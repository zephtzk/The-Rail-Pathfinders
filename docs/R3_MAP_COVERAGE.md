# R3 map coverage and address search

Reviewed 19 September 2026. The user's screenshot shows a map-tile access rejection, not missing Singapore geography.

## Singapore coverage

OpenStreetMap has map data across Singapore. Its [Singapore mapping project](https://wiki.openstreetmap.org/wiki/Singapore) links to the country map and describes roads, buildings, transport and boundaries. A current downloadable regional extract that includes Singapore is available from [Geofabrik](https://download.geofabrik.de/asia/malaysia-singapore-brunei.html).

This is geographic coverage, not proof that every address, footpath, toilet, lift, indoor level or accessible connection is complete or current. The Singapore project explicitly lists remaining work on building/address information and missing names. Commute Copilot's supported routing still comes from its imported timetable and reviewed connections. A visible map feature or geocoded point never establishes a safe station entrance or accessible walking connection.

## Why the map was blocked and what changed

The R2 Worker sent `Referrer-Policy: no-referrer` for all application assets, including HTML. The [OSM tile usage policy](https://operations.osmfoundation.org/policies/tiles/) requires browser requests to send a valid Referer and explicitly forbids a restrictive policy that suppresses it. This is a concrete policy mismatch consistent with the screenshot; the server's precise decision cannot be established from that screenshot alone.

R3 application responses use `strict-origin-when-cross-origin`. The shared street-map helper additionally sets each tile request's `referrerPolicy` to `origin`, including when an older HTML response remains cached. Only the application origin is sent cross-site. Sharing APIs continue to use `no-referrer`; invitation secrets stay in fragments and are removed by the existing handler.

Tiles retain visible attribution and normal browser caching. They are excluded from service-worker/offline downloads. Visible tiles use CORS fetches to check HTTP status and image content before displaying a blob URL: Edge can otherwise display a valid error image even with HTTP 403. A failed request removes the street-map layer, leaves route overlays visible and reports a plain-language fallback. Requests are cancelled and temporary blob URLs released when tiles unload. Recovery requires a deliberate retry; there is no automated provider rotation or bulk fetching. A replacement provider must support CORS and include matching attribution. OSM community tiles remain best effort, with no service guarantee.

## Saved-place address search

[Photon's official service](https://photon.komoot.io/) and [project documentation](https://github.com/komoot/photon#demo-server) permit fair, modest API use, with throttling or blocking for excessive requests and no availability guarantee. This is a distinct provider from the public Nominatim service. An explicit Search button, short client cooldown, bounded results, a Singapore filter and in-memory caching keep the prototype's requests small. A user must select a returned candidate; text alone must not be treated as resolved coordinates.

The [Photon API](https://github.com/komoot/photon/blob/master/docs/api-v1.md) supports `q`, `countrycode=SG`, a `bbox` in west/south/east/north order, a result limit and `lang=en`. The provider may omit addresses or return a building centre rather than an entrance. Save the provider/source with the candidate and keep route/accessibility eligibility separate.

The [Photon maintainer's privacy explanation](https://github.com/komoot/photon/discussions/539) says the public instance keeps request logs for limited operational use. Explain that submitted address searches go to Photon; do not silently submit personal saved-place labels. Larger or sensitive production usage should use a separately operated or contracted search provider.

[OneMap](https://www.onemap.gov.sg/apidocs/) is Singapore Land Authority's national map service. Its [Search API](https://www.onemap.gov.sg/apidocs/search) returns address and coordinate candidates, but now requires an Authorization token. [Tokens last three days](https://www.onemap.gov.sg/apidocs/authentication), so a future integration should use server-held credentials and renewal. The [documented authentication checks](https://www.onemap.gov.sg/apidocs/docs/verifyingsearchapitoken) include errors in otherwise successful HTTP responses; callers must inspect the JSON too. No unauthenticated legacy endpoint is assumed to work.

The public [Nominatim policy](https://operations.osmfoundation.org/policies/nominatim/) prohibits client autocomplete and restricts generic geocoding generated by no-code, low-code or vibe-coding platforms. R3 does not use that public service.

## Verification scope

`tests/network-map.test.mjs` verifies origin-only tile referrers, attribution, failure-layer removal, preserved overlays, no automatic retries, deliberate recovery and offline startup. These checks do not establish continuous external-provider availability or complete geographic/address coverage.

`tests/r3-map-browser.mjs` passed four checks in Edge against the integrated local server: the browser sent only the application origin as the tile Referer, a valid image body with HTTP 403 was rejected, station/route overlays remained visible, and the map recovered after explicit retry without browser runtime errors. The test intercepts external tiles with controlled responses; it does not download a map region.

Live read-only smoke checks on 19 September 2026 submitted the public landmark `Changi Airport` to Photon with the documented Singapore filters. It returned HTTP 200, a GeoJSON FeatureCollection and six Singapore point candidates with OSM source identifiers. A normal Singapore OSM tile request (`12/3229/2032`) with an identifying application User-Agent and `Referer: http://localhost:4193/` returned HTTP 200, a PNG signature and browser-cache headers. A follow-up header check confirmed `Access-Control-Allow-Origin: *` for CORS tile fetching. No map images or search-response payloads were saved. This establishes that these requests worked from the development host at that time, not an uptime or data-completeness guarantee.
